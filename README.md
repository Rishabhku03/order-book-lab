# Order Book Lab

A C++20 limit order book replay engine with an independent Python checker, reproducible performance experiments, and a browser viewer.

The engine processes synthetic order events for one instrument. It supports additions, cancellations, deletions, executions and replacements. Executions identify existing orders; the engine does not match orders or model trading profitability.

## Try it locally

```text
python -m pip install -r requirements-dev.txt
python tools/run.py doctor
python tools/run.py build
python tools/run.py test
python tools/run.py demo
```

The last command opens the viewer at `http://127.0.0.1:8765`. Use Ctrl+C to stop its local server. No account, API key, database or paid data is required. The viewer displays output generated by C++; playback speed is unrelated to engine throughput.

Windows requires Microsoft C++ Build Tools with the Desktop development with C++ workload. The launcher finds its compiler environment automatically. Linux requires GCC or Clang and standard build tools. CMake downloads four dependencies on the first build, each pinned by commit and SHA-256. Subsequent builds reuse the local cache.

The included Pages workflow publishes the `web` directory after verification. Deployment is started manually once the repository and Pages settings are configured.

## Design

- Three implementations share event semantics and price-level storage: an ordered order-ID map, a hash map, and a hash map with reserved capacity.
- Bids and asks have separate ordered price maps. Each level stores aggregate quantity and order count.
- Integer ticks, checked arithmetic, and validation before mutation prevent floating-point keys and rejected partial updates.
- Public snapshots own their data. No references to mutable internal storage escape.
- The independent checker recomputes levels from all active orders after each event.
- The viewer reads saved JSON locally and accepts compatible trace uploads. Uploaded files stay in the browser.

An update combines order-ID lookup with ordered price-level updates. Tree lookup costs O(log N); hash lookup is expected O(1), with O(N) worst cases and possible rehashing. Price-level changes cost O(log L), where N is the active-order count and L the occupied levels on a side. Depth snapshots traverse only the requested levels. Reservation changes allocation behavior; it does not change the event contract or guarantee faster processing.

See [the event contract](docs/EVENTS.md) for precise behavior, including missing analytics, replacement rules and failure handling.

## Performance scope

Book-update measurements exclude input parsing, file reads, analytics traversal and output. Separate measurements include those costs. Instrumented event latency includes timer overhead and excludes network transport and queueing. Process memory is working set on Windows and RSS on Linux, not exact per-order allocator usage.

Synthetic workload sizes change both the maximum live orders and available price levels. These experiments measure implementation behavior under documented generated inputs. They do not validate a market model.
